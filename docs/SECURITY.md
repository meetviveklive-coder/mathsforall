# Security & Privacy Guidelines

The site has no accounts and no backend, so most of the template's sections reduce to
"not applicable". What remains matters more: this site is used by children.

## 1. Authentication
None. No sign-up, sign-in, or user identifiers.

## 2. Authorization
None at run time. Publishing is controlled by Git access (only the maintainer merges to `main`).

## 3. Secrets
- The site has no runtime secrets.
- Any API keys used by the authoring pipeline live in the author's environment, never in the repo.
- `.env*` files are git-ignored.

## 4. Environment Variables
Public: none.
Private (authoring only): none required for the pilot.

## 5. Web Security
- Content Security Policy: `default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; script-src 'self'; connect-src 'self'; frame-ancestors 'none'`
- No third-party scripts, fonts, analytics, ads or embeds.
- Content JSON is rendered as text/markdown with HTML escaped; no raw HTML from content files.
- SVG diagrams are generated by our own scripts and sanitised at build (no `<script>`, no event attributes, no external refs).

## 6. Data Protection (children)
- Collected personal data: none.
- Progress stays in the learner's browser; export files contain no personal data.
- India DPDP Rules 2025 (notified 14 Nov 2025): verifiable parental consent is required to process a child's personal data, with most obligations in force about 18 months after notification. This design avoids processing personal data entirely. Any future feature that collects data (accounts, AI tutor, voice) requires a fresh privacy review and legal advice before build. (Not legal advice.)
- "Report a mistake" must not collect names or emails from children; it should open a pre-filled report containing only the question ID.

## 7. Logging
No runtime logging or telemetry. Hosting provider access logs are outside our control; do not enable extra analytics.

## 8. File Uploads
None. Progress import accepts only our JSON export format, validated and size-limited (≤ 1 MB) before use.

## 9. Content Safety
- Word problems use neutral, age-appropriate contexts; no brands, real people (except historical mathematicians), violence, or gambling framing.
- Avoid stereotypes (gender, caste, region, religion) in names and roles; rotate names across India's regions.

## 10. Security Checklist
- [ ] No third-party requests on any page (verified in browser network panel)
- [ ] CSP header set in `_headers`
- [ ] Content rendering escapes HTML
- [ ] SVGs sanitised
- [ ] Import validates and size-limits files
- [ ] No personal data fields anywhere in progress schema
- [ ] Dependencies reviewed (`npm audit`) before each release
